# Architecture decision log

Each entry: context → decision → consequence. Deviations from the master specification are
marked **(deviation)**.

### D1 — pnpm workspace, TypeScript 6, project references
Expo SDK 58 ships TypeScript 6.0, so the whole repo uses 6.0.x (strict, `noUncheckedIndexedAccess`).
Packages compile to CommonJS `dist/` for Node (API) and expose `src/` through the `react-native`
export condition for Metro. pnpm uses `nodeLinker: hoisted` for React Native compatibility.

### D2 — Native recording with a durable journal
Location capture lives in Swift; every fix is fsync'd to a per-activity journal before JS is
notified, JS persists to SQLite and acknowledges. This makes data loss require both the journal
write and the SQLite write to fail, and lets recordings survive JS suspension or crashes.

### D3 — Deterministic replay as the recovery and testing mechanism
Events store `afterSampleCount`, so replay reproduces the live session exactly. The same mechanism
restores backups (only source data is backed up) and powers GPS tests.

### D4 — Local SQLite with hand-written SQL instead of Drizzle on device **(deviation)**
The spec lists Drizzle for both sides. On device, repositories use a 5-method `SqlDriver` interface
so the identical SQL runs on expo-sqlite and on `node:sqlite` in tests, with explicit migrations.
Drizzle is used for PostgreSQL in the API. Revisit if query complexity grows.

### D5 — `route_points` natural primary key **(deviation)**
The spec lists a UUID `id`. `(activity_id, sequence_number)` is unique by construction, makes
inserts idempotent (retries, sync batches) and keeps the largest table compact (`WITHOUT ROWID`).

### D6 — Kalman-filtered distance
Pure anchor/threshold filtering inflated noisy tracks by 11 % and stationary drift by kilometres.
An accuracy-weighted position filter fixed both; its ≈3–4 m lag is recovered at segment close
(audit F17).

### D7 — Charts built from Views instead of Victory Native **(deviation)**
Victory Native (current major) requires Skia, Reanimated and gesture-handler native modules. The
app needs simple bar charts; a View-based chart avoids ~3 native dependencies and binary size.
Swap in Victory Native when richer charts (zoomable time series) are needed.

### D8 — Map provider abstraction with tile-free fallback
`RouteMap` uses MapLibre when `EXPO_PUBLIC_MAP_STYLE_URL` is configured, otherwise draws the
route as SVG. No tile provider is hardcoded and public OSM tiles are not used.

### D9 — jose v5, noble v1, NestJS 11 pinned
`jose` 6 and `@noble/*` 2 are ESM-only, which conflicts with the CommonJS Jest/Nest toolchain;
v5/v1 are maintained, dual-format and API-compatible for our use. NestJS 11 was chosen over the
newest major for ecosystem stability. Upgrade together with an ESM migration of the API.

### D10 — Cloud backups are always client-side encrypted
The API rejects unencrypted backups. Cloud backups use a device-held random recovery key; local
files use a passphrase (scrypt). The server can never read activity data.

### D11 — Sync scope v1: push activities only
The outbox records activities and goals; v1 pushes activities (metadata, then route batches).
Goal sync and multi-device pull are deferred; goal entries remain queued rather than being
reported as synced.

### D12 — Merged `core`/`shared-types` responsibilities
`domain` holds shared types (the spec's `shared-types`); `core` holds application services that
combine packages (import/export, backup/restore, analytics). Module boundaries are preserved.

### D13 — Native projects generated (CNG)
`apps/mobile/ios` is generated by `expo prebuild` and not committed; native source lives in
`apps/mobile/modules/pace-tracking`. The spec's `ios/PACETracking` maps to that module.

### D14 — Testing approach for UI
React Native Testing Library would need a full RN Jest runtime; at this stage UI coverage is
provided by Maestro flows (device/simulator) and logic is kept out of components and unit-tested.
RNTL tests are planned once a macOS CI runner is available.

### D15 — Process-wide native recorder, no automatic restart (audit F2)
A JS reload must not stop a recording, so the recorder outlives Expo module instances. A process
restart must not silently resume, or downtime would count as moving time; the activity is recovered
as `INTERRUPTED` and the athlete decides.

### D16 — Single-connection SQLite with an in-process lock (audit F3)
`withExclusiveTransactionAsync` uses a separate connection without our pragmas. All statements run
on one configured connection, and a JS lock guarantees transactions are never interleaved.

### D17 — Raw samples validated for type only at boundaries (audit F4)
Plausibility belongs to the GPS engine, which stores and rejects. Rejecting at the boundary breaks
the gap-free sequence and backups.

### D18 — Smoothed elevation and Doppler stationary gating (audit F15, F16)
Parameters (τ = 10 s, 5 m; per-sport Doppler thresholds) come from the replay suite's correlated
error model; see the audit for the sweep and tolerances.

### D19 — macOS CI only on native changes; full iOS suite on demand
macOS minutes are billed at 10x on private repositories. Measured job times (runs 43105734303,
43137368039): setup ~3 min, Swift tests ~0.5 min, Debug build 17-26 min, Release build ~28 min.
Before: every push to `main`/`ci/**` ran a Debug job and a Release launch job (~55-65 macOS min,
~550-650 billed min), and a pull request from a `ci/**` branch ran them twice. Now: Linux checks
on every change (unchanged); Swift tests (~2 min, ~20 billed) only when native module code
changes; the full suite (~55 min, ~550 billed; ~35 min without the Debug build) as one job,
manually or via the `ios-full-verification` PR label, before releases and native merges.
Trade-off: a dependency or config change can break the iOS build without an automatic signal
until the next full run, so the full suite is required before merging such changes.
